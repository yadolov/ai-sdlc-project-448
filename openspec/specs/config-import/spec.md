# Импорт конфигурации

## Purpose

Формат файла конфигурации и правила его разбора — парсер принимает JSON-файл, извлекает
пользователей, группы, сервисы и разрешения, проверяет целостность и возвращает готовую
конфигурацию или список ошибок. Файл также используется для экспорта и хранения в браузере —
трёхсторонний формат единый.

## Requirements

### Requirement: Формат файла конфигурации

Файл конфигурации **MUST** быть JSON-объект с обязательным полем `version` (целое число) и четырьмя
списками: `users`, `groups`, `services`, `permissions`. Идентификаторы внутри каждого списка **MUST** быть
уникальны. Разрешения и участие пользователей в группах **MUST** ссылаються на существующие записи.

#### Scenario: Валидный файл импортируется без ошибок

- **GIVEN** валидный JSON-объект с `version`, `users`, `groups`, `services` и `permissions`
- **WHEN** файл передаётся на парсинг
- **THEN** результат содержит готовую конфигурацию

#### Scenario: Пустая конфигурация принимается

- **GIVEN** объект с пустыми списками и валидной версией
- **WHEN** файл передаётся на парсинг
- **THEN** результат содержит пустую конфигурацию

#### Scenario: Неизвестные поля игнорируются

- **GIVEN** файл с дополнительными полями (например `exportedBy` или `nickname`)
- **WHEN** файл передаётся на парсинг
- **THEN** дополнительные поля игнорируются, конфигурация успешно импортируется

#### Scenario: Файл записан и прочитан обратно — идентичность

- **GIVEN** любая валидная конфигурация
- **WHEN** она экспортируется в JSON и затем импортируется
- **THEN** результат парсинга идентичен исходной конфигурации

### Requirement: Проверка версии формата

Поле `version` **MUST** присутствовать и быть целым числом. Файлы с версией новее поддерживаемой
отвергаются.

#### Scenario: Отсутствующее поле version отвергается

- **GIVEN** валидный JSON-объект без поля `version`
- **WHEN** файл передаётся на парсинг
- **THEN** возвращается ошибка «Нет поля version с целым числом»

#### Scenario: Версия не целое число отвергается

- **GIVEN** объект с полем `version`, содержащим строку или дробное число
- **WHEN** файл передаётся на парсинг
- **THEN** возвращается ошибка «Нет поля version с целым числом»

#### Scenario: Версия новее поддерживаемой отвергается

- **GIVEN** объект с `version` больше текущей поддерживаемой версии
- **WHEN** файл передаётся на парсинг
- **THEN** возвращается ошибка с указанием версии файла и поддерживаемой версии

### Requirement: Валидация структуры записей

Каждый элемент списков `users`, `groups`, `services`, `permissions` **MUST** быть объектом с
обязательными полями. Списки `users` и `permissions` содержат дополнительные поля.

#### Scenario: Отсутствующий список отвергается

- **GIVEN** объект без одного из обязательных списков (например `groups`)
- **WHEN** файл передаётся на парсинг
- **THEN** возвращается ошибка «Поле <key> должно быть списком»

#### Scenario: Обязательные поля объекта должны быть непустыми строками

- **GIVEN** элемент списка, в котором обязательное поле (например `name`) отсутствует или
  имеет неверный тип
- **WHEN** файл передаётся на парсинг
- **THEN** возвращается ошибка с указанием поля и позиции: «<key>[<index>]: поле <field> должно
  быть непустой строкой»

#### Scenario: subject у разрешения — объект с типом user или group

- **GIVEN** разрешение с `subject`, который не объект или имеет неизвестный `type`
- **WHEN** файл передаётся на парсинг
- **THEN** возвращается ошибка: «<key>[<index>]: поле subject должно быть объектом» или
  «<key>[<index>]: тип субъекта должен быть user или group»

### Requirement: Уникальность идентификаторов

Внутри каждого списка (`users`, `groups`, `services`, `permissions`) все идентификаторы **MUST**
быть уникальны.

#### Scenario: Повторяющийся идентификатор в одном списке отвергается

- **GIVEN** список, в котором два элемента имеют одинаковый `id`
- **WHEN** файл передаётся на парсинг
- **THEN** возвращается ошибка: «<key>[<index>]: идентификатор «<id>» уже занят»

### Requirement: Ссылочная целостность

Разрешения **MUST** ссылаться на существующих пользователей или группы (через `subject`) и на существующие
сервисы (через `serviceId`). Пользователи **MUST** ссылаться на существующие группы (через `groupIds`).

#### Scenario: Разрешение на несуществующего пользователя отвергается

- **GIVEN** разрешение с `subject.type: "user"` и `id`, которого нет в списке `users`
- **WHEN** файл передаётся на парсинг
- **THEN** возвращается ошибка: «permissions[<index>]: нет пользователя «<id>»»

#### Scenario: Разрешение на несуществующую группу отвергается

- **GIVEN** разрешение с `subject.type: "group"` и `id`, которого нет в списке `groups`
- **WHEN** файл передаётся на парсинг
- **THEN** возвращается ошибка: «permissions[<index>]: нет группы «<id>»»

#### Scenario: Разрешение на несуществующий сервис отвергается

- **GIVEN** разрешение с `serviceId`, которого нет в списке `services`
- **WHEN** файл передаётся на парсинг
- **THEN** возвращается ошибка: «permissions[<index>]: нет сервиса «<id>»»

#### Scenario: Пользователь в несуществующей группе отвергается

- **GIVEN** пользователь с `groupIds`, содержащим `id` группы, которой нет в списке `groups`
- **WHEN** файл передаётся на парсинг
- **THEN** возвращается ошибка: «users[<index>]: нет группы «<id>»»

### Requirement: Сбор всех ошибок

Парсер **MUST** собирать все ошибки валидации файла целиком, а не останавливается на первой.

#### Scenario: Несколько ошибок возвращаются списком

- **GIVEN** файл с несколькими нарушениями (например, ссылка на несуществующий сервис и
  несуществующую группу)
- **WHEN** файл передаётся на парсинг
- **THEN** возвращается список всех ошибок, а не только первая

### Requirement: Поведение при загрузке из хранилища

При чтении сохранённой конфигурации из браузера (`loadConfig`) результат парсинга **MUST** использоваться
напрямую. Если файл не распарсился или повреждён — **MUST** возвращатья учебная конфигурация (`seedConfig`).

#### Scenario: Пустое хранилище отдаёт учебные данные

- **GIVEN** хранилище не содержит ключ конфигурации
- **WHEN** вызывается `loadConfig`
- **THEN** возвращается `seedConfig`

#### Scenario: Повреждённое хранилище отдаёт учебные данные

- **GIVEN** в хранилище сохранён невалидный JSON
- **WHEN** вызывается `loadConfig`
- **THEN** возвращается `seedConfig`

#### Scenario: Хранилище с нарушенной целостностью отдаёт учебные данные

- **GIVEN** в хранилище сохранена конфигурация, которая не проходит проверку ссылок
- **WHEN** вызывается `loadConfig`
- **THEN** возвращается `seedConfig`

#### Scenario: Валидная конфигурация из хранилища возвращается как есть

- **GIVEN** в хранилище сохранена валидная конфигурация
- **WHEN** вызывается `loadConfig`
- **THEN** возвращается сохранённая конфигурация
